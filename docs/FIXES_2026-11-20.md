## 2. 潜在偏差

### B1 mask 与影像缓存卷几何不一致（含轴序）
- 原行为：`load_mask_resized` 用 nibabel 读 mask（轴序 `x,y,z`），直接 `Resize(96³, nearest)`；而缓存卷是 `sitk.GetArrayFromImage`（`z,y,x`）+ `Spacing(1mm) → 窗 → CropForeground → Resize`。轴序与物理网格双错位。
- 改动：新增 `load_mask_96(...)`：
  - CT：MONAI 字典变换 `LoadImaged → EnsureChannelFirstd → Spacingd(1mm) → ScaleIntensityRanged → CropForegroundd(source_key="ct") → Resized(nearest)`，与 `_ct_deterministic` 逐步对齐；
  - MRI：`_mri_reference_grid(anchor)` 建 1mm 参考网格 → mask 最近邻重采样 → 用锚序列 nonzero bbox 裁剪 → `Resize(nearest)`，与 `_mri_seqs_deterministic` 对齐；
  - 内存 memo + 失败显式告警；`--mask-geometry legacy` 保留旧路径。
- 影响面：`train_roi_dl.py` 全部 mode（ct / mri_* / mri_c_ct），以及依赖其掩码的 ring 实验；`tools/s0_vis_roi.py` 同步改用 aligned 掩码，否则叠加图仍按旧错位几何绘制。
- 单样本只读验证（pid=1）：task010 由 133 体素（legacy）→ 190 体素、z 范围 27-32（aligned）；mr_t 17681 体素，均落在 96³ 内，管线可跑通。
- 需重跑：**是**（属口径变更，见 §0）。

### B2 DL 概率 Stacking 使用 in-sample train 概率
- 原行为：stacking 的 train 端 DL 概率来自在 train 上训练的 ckpt，CV 指标系统性偏乐观，且结果未标注。
- 改动：`radiomics_experiment.run_stacking` 返回体新增 `note`；`roi_experiment` 报告打印该 note。未伪造 OOF（需训练侧支持）。
- 影响面：M4 / CRCFound stacking 的 CV 列解读。
- 需重跑：**是**（要得到无泄漏 stacking 需 5-fold OOF 概率，属训练侧改造）。

### B3 N 头误用 T 的类别权重
- 原行为：`train_roi_dl.py`、`train_2p5d.py`、`train_mil.py` 均为 `crit_n = CE(weight=w_t)`，与 `config/hos.py:76` 注释「N 分布均衡，不加权」矛盾。
- 改动：三处均改为 `w_n = _inv_w(labels_N)`，训练开始日志打印 T/N 权重；ROI 报告的 meta 增加 `n_weight: inverse(label_N)`。
- 影响面：三个实验的全部 N 指标，及 README 中「ROI-DL N 突破主模型」的对比。
- 需重跑：**是**（口径变更，见 §0）。

### B4 2.5D / MIL 校准取自末轮权重，`best_acc` 取各轮最大值
- 原行为：训练结束后直接用最后一轮的 `pt/pn` 校准；`best_acc = max(curves["val_acc"])` 与保存的 best ckpt 不对应。
- 改动：新增 `_val_probs()` 重新加载 `best_model[_n]_2p5d|mil_*.pth` 后计算概率再校准；`best_acc` 取 `curves["val_acc"][best_epoch-1]`。
- 影响面：`logs/eval_report_2p5d_*` / `eval_report_mil_*` 的 calT/calN/best_acc。
- 需重跑：**是**（口径变更，见 §0）。

### B5 临床 7 维 z-score 用全队列统计
- 核查结论：**"完全没标准化"不成立**。`data/hos_pairs.csv` 的 age/sex/ca199/cea/albumin/prealbumin/hb 已是 z-score（实测均值≈0），由 `build_hos_batch2/3_csv.py` 用全队列计算后写盘。
- 真实问题：标准化统计量包含验证集样本（轻度信息泄漏），且离群值未裁剪（albumin 最大 14.9σ、prealbumin 17.8σ）。
- 改动：**未改数据、未改训练**。仅在本记录标注：彻底修复需把 z-score 移到「按 split-seed 用 train 行统计」，属数据契约变更。
- 影响面：所有使用临床特征的实验。
- 需重跑：**是**（若采纳 train-only 标准化）。

### B6 `valid` 掩码未参与 loss
- 原行为：`valid=(lt>=0)&(ln>=0)` 计算后未用于 CE，标签 -1 会直接进 `CrossEntropyLoss`。
- 改动：三脚本新增 `_tn_loss()`，按任务分别用 `vt/vn` 索引后再算 CE；loss 累加权重计数同步修正。
- 影响面：当前全量 csv 无 -1 标签，故对既有数字无影响；分支/kfold csv 不再崩溃。
- 需重跑：否（数值等价）。

### B7 radiomics 特征读取失败静默填零
- 原行为：`_load_ct_vol/_load_mri_vol` 裸 `except` 返回 None，整段特征填 0 且无日志；MRI 恒定传 `[True,True,True]`。
- 改动：`extract_features` 增加 `n_fail_ct / n_fail_mri` 计数并按 split 打印；空特征表显式抛错；docstring 标注 ckpt 实为 s0。
- 影响面：`radiomics_experiment` / `roi_experiment` / `crcfound_features` 的特征表可信度。
- 需重跑：否（仅为可观测性）。

### B8 ring 只算质心，从未屏蔽图像
- 核查结论：**成立**。原 `crop_roi(ct, mask)` 只用 `mask` 求质心，影像未做任何掩码或通道拼接；`load_mask_resized` 的 ring 结果仅影响质心位置，因此 ring 与 body 的输入几乎相同（同一 64³ 立方体，中心差几个体素）。
- 改动：`crop_roi(..., mode=)` 支持 `centroid / bbox / masked`；`masked` 会把 mask 外体素置 0；新增 `--roi-mask`，默认 `centroid`（与历史完全一致）。
- 影响面：所有 ring 实验的结论解释。
- 需重跑：**是**。`--roi-mask masked` 才是真正的「仅环内组织」实验；现有 ring/body 对比不能支持系膜腔室假设。

### B9 k-fold 折内训练集传入全量标签
- 核查结论：**成立**。`_SubDS(base, tr_idx, lab_t=lab_t, ...)` 传入全量 280 条标签，`run_one` 用它算类别权重 → 验证折标签分布参与权重统计。
- 改动：折内标签按索引切片（`lab_t/lab_n/lab_pt` 三组同步），并按折写入报告的 `mask_geometry/roi_mask`。
- 影响面：ROI-DL 5-fold 的类别权重。
- 需重跑：**是**（权重变化）。

## 8.1 模态 dropout 未播种（trainers/trainer.py:238-247）
- 原行为：`_sample_modality_masks` 用 Python `random.random()`；`run_seed`/`run_kfold` 只 `torch.manual_seed`/`np.random.seed`，`random` 状态随进程漂移。
- 改动：`train_hos_seeds.py` 新增 `_seed_everything(seed, deterministic)`：`random.seed` + `np.random.seed` + `torch.manual_seed` + `torch.cuda.manual_seed_all`；`deterministic=True` 时设 `cudnn.deterministic=True / benchmark=False`。run_seed（L647）与 kfold（L805）均改用该函数；新增 CLI `--deterministic`（默认关闭，向后兼容），落到 `HosConfig.deterministic`。
- 影响面：所有训练 run 的 dropout 序列；不改变默认数值口径时也改变随机序列 → 旧 run 不可逐位复现。

## 8.2 `modality_dropout["both"]` 死键（trainer.py:238-239 / config/hos.py:66 / train_hos_seeds.py:177→现 194）
- 原行为：采样只读 `ct_only`/`mri_only`，`--md-both` 仅写入配置、从不参与采样。
- 改动：`_sample_modality_masks` 按 `[mri_only, ct_only, both]` 三键归一化后采样；默认 0.15/0.15/0.7（config 为 0.20/0.15/0.65）三者和为 1，逐样本映射与旧版完全一致；`both` 缺省按 `1-ct_only-mri_only` 补。
- 影响面：`tools` 与主入口所有训练；单模态消融（`both=0`）行为不变。
- 验证：2 万样本统计，默认 CT 保留 0.7998 / MRI 保留 0.8503（= 1-0.20/1-0.15）；`--md-both 0.9` 时 CT 丢弃率 0.158、MRI 0.121（归一化后生效）。

## 8.3 不确定性加权非 Kendall 标准式（trainer.py:340-348）
- 原行为：`exp(-log_var)·L + 0.5·log_var`（缺 0.5 系数，等价于把任务项放大 2 倍）。
- 改动：`0.5·exp(-log_var_t)·L_t + 0.5·exp(-log_var_n)·L_n + 0.5·log_var_t + 0.5·log_var_n`；仅在 `--uncertainty-weight` 开启时生效。
- 影响面：所有开启不确定性加权的 run（round9 S9-1 系列），其损失尺度与 T/N 相对权重改变。

## 8.4 MixUp 第二标签类别权重（trainer.py:307-315）
- 原行为：`per = (λ·nll_a+(1-λ)·nll_b) · weight[target]`，第二标签 `target[idx]` 误用第一标签权重。
- 改动：`per = λ·weight[target]·nll_a + (1-λ)·weight[target[idx]]·nll_b`；`weight=None` 路径不变。
- 影响面：`--mixup>0` 且 `class_weight_mode != none` 的训练（T/N/aux 三个 CE 共用该函数）。

## 8.5 `log_var` 未进调度器（trainer.py:90-97 vs 原 122-129）
- 原行为：先建 `CosineAnnealingLR/WarmRestarts`，后 `add_param_group(log_var)`，日志方差参数 lr 恒定不变。
- 改动：把不确定性参数组的创建移动到 scheduler 之前，保证 `log_var_t/n` 纳入余弦调度。
- 影响面：开启 `--uncertainty-weight` 的 run。

## 8.6 划分是否按病人分组（仅验证，未改代码）

| hos_full_train_s0/s1/s42/s7 | 284 | 284 | 0 |

- **结论：已验证无病人级泄漏，data/hos_pairs.csv 及当前使用的划分 csv 中 patient_id 全局唯一（1 行 1 病人），不做 GroupShuffleSplit**，保持既有划分逻辑与历史结果可比性。

## 8.8 split csv 文件名未体现 split_seed（train_hos_seeds.py:674-682）

- 改动：注释更正为"T/N 各按本任务标签满逆频率加权"；同时更新 `modality_dropout` 的过时样本分布注释（39/24/92 为 154 样本时代）。

## 8.10 MixUp 分支 N 头未传类别权重（trainer.py:324-327）

- 改动：Trainer 保存 `self.class_weights_n`，MixUp 分支传入；与 T/aux 分支一致。
- 影响面：`--mixup>0` 的多任务 run。

## 8.11 N 头输入维度重复计数（models/network.py:229-233）
- 原行为：`n_from_shallow=False` 分支中，`n_in = classifier_in`（开启 `mri_lesion_fusion` 时已含一次 ROI 嵌入宽度），`n_lesion_fusion` 又加一次；forward 只拼一次 `mri_lesion_emb` → 同时开两个 ROI 融合开关时 Linear 输入维度多算一个 `mri_lesion_head_width`，必然 shape 报错。
- 改动：仅当 `n_lesion_fusion and not mri_lesion_fusion` 时追加宽度；`n_from_shallow=True` 分支原本只加一次，保持不变。
- 影响面：同时使用 `--mri-lesion-fusion --n-lesion-fusion` 且 `n_from_shallow=False` 的配置（此前不可运行）。

## 8.12 validate 空 val 时 NameError（trainer.py:649）
- 原行为：`n_acc = ... if correct_n > 0 or "n" in out else nan` 引用循环变量 `out`，val loader 为空时未定义。
- 改动：循环前 `has_n_out=False`，命中 N 输出时置 True；`n_acc = correct_n/max(total,1) if has_n_out else nan`。

## 8.13 `--eval-only` 日志回退正则不匹配 kfold（train_hos_seeds.py:438-471）
- 原行为：`re.sub(r"^(?:s|k\d+_f\d+)", ...)` 不匹配 `run_label="k0"` → 拼出 `crc_..._seedk0*.log`，永远查不到日志，静默返回全 0。
- 改动：kfold 分支改为定位 `logs/crc_{tag}_kfold*.log`，用 `^--- Fold {i}:` ~ 下一 Fold 截取该折段落再解析；holdout 分支只剥离 `s` 前缀。报告 JSON 存在时仍优先读 JSON。

## 8.14 CUDA 播种与 cudnn 确定性（train_hos_seeds.py:625-626）

- 改动：并入 8.1 的 `_seed_everything`，并在 `--deterministic` 时关闭 benchmark。
- 影响面：多卡/GPU 训练的复现性；默认不改变数值（不强制 deterministic）。

## 11.5 第 9 条：原始临床极值核查结论

| 列 | 原始分布（`hos_pairs_raw.csv`） | 极端样本 | 判定 |
|---|---|---|---|
| albumin | n=322，min 0，max 440，q01 26.21，q99 135.32，mean 40.8，sd 26.7 | 306=440；402=182；314=151；328=0；205=1.46 | 306 疑似 ×10 单位错（≈44 g/L）；402/314 >100 g/L 生理不可能（疑录入/单位错）；328 的 0 为**缺失写成 0**；205=1.46 疑小数点错位（≈146？） |

| 任务 | AUC mean±std | 判读 |
|---|---|---|
| label_T | 0.5835 ± 0.0301（5 折全 >0.52） | 弱但方向稳定的独立信号 |
| label_N | 0.5255 ± 0.0670（fold3 = 0.4206） | 无可用信号，折间波动大于均值增益 |

补充事实：ca199/cea 缺失约 66%（236/234 例），age 缺失 28%；14 维（7 值 + 7 指示位）在 284 例训练集上，容量/缺失结构决定的过拟合风险高于潜在收益。

**定案（不再列为待确认）**：

| # | 决策 | 依据 |
|---|---|---|
| 1 | P0 **主表全部 `--no-clinical`**；带 clinical 版本只作 T 头消融，不进主表 | §13.4：T 弱信号、N 无信号；ca199/cea 缺失约 66% |
| 2 | 主线锁定 `--mode mri_t`（本体/对照）与 `mri_t_ring`（5mm 环）；多序列（`mri_tc` / `mri_all` / 含 CT）后置 | 单序列样本量最大、变量最少，先把 ring/SDF 的作用分离出来 |
| 3 | CT 的 `--sdf-channel` **不阻塞 P0**，推迟到进入 CT 分支前补测 | CT aligned 路径既有 `Spacingd` 全幅 1mm 成本（单例 >60s），与 SDF 逻辑无关 |

- 带 clinical 的版本**只作 T 头消融**（第三段），不与主表数字混排。
- 注意口径：§13.4 中 T 的 **AP 0.7978 不能当作有效性证据**——T 阳性率 254/356 = **0.714**，AP 0.798 仅比“全判阳性”的基线（AP≈0.714）高约 0.08，且 PR-AUC 对类别不平衡天然偏高；判读须与阳性率并列，不能单看 AP。

## 14.2 三段式执行计划

### 14.2.1 第一段：标定（1 臂 × 1 折，仅测成本；**未执行**）

| 项 | 内容 |
|---|---|
| 臂 | `--mode mri_t --roi-mask bbox`（无 ring、无 SDF，与第二段 B/C 同中心口径） |
| 折/种子 | `--kfold 5 --only-fold 0` + seed42 |
| 目的 | 只实测**单折墙钟耗时**与**显存峰值**，用于推算第二段的 GPU 预算；不产出可引用指标 |
| 记录 | 每 epoch 耗时、单折总耗时、`torch.cuda.max_memory_allocated()` 峰值、数据加载等待占比 |
| 命令（未执行） | `python tools/train_roi_dl.py --kfold 5 --kfold-csv data/master_5fold_356.csv --only-fold 0 --full-csv data/hos_pairs.csv --mode mri_t --roi-mask bbox --no-clinical --self-written --head-dropout 0.5 --seed 42 --out-tag p0_cal_mri_t_bbox` |

理由：历史“约 20 分钟/折”是 **30ep 主模型（2.5D/主入口）** 的数字（README 既有记录），其输入尺度、模型与 batch 均与 ROI 分支不同，**不能套用到 ROI-DL**；第二段 15 个 run 的排期必须以本段实测为准。`--only-fold` 只训练指定折，其余折不跑，故本段 LOFO 阈值为 None（单折无 OOF），只报最佳 ckpt 与末 5 轮两套指标。

### 14.2.2 第二段：主线（3 臂 × 5 折，全部 `--no-clinical`；**未执行**）

| 臂 | 命令关键参数 | 假设/作用 |
|---|---|---|
| A. ring 5mm | `--mode mri_t_ring --ring-mm 5 --roi-mask masked` | 只喂肠周/系膜环内组织，检验“系膜腔室信息”是否优于含腔内容物 |
| B. SDF 双通道 | `--mode mri_t --sdf-channel --roi-mask bbox`（不叠加 `--ring-mm`） | 原图灰度 + 连续物理距离场，保留距离信息且不二值化 |
| C. bbox 对照 | `--mode mri_t --roi-mask bbox`（第一段同配置补齐 5 折） | 主表基线，与 A/B 同折同 seed 对比 |

- 全部 seed42 × 5 折，折划分固定取 `data/master_5fold_356.csv`（§13.1 已核实可用：356 唯一患者、无 -1/NaN），并显式 `--full-csv data/hos_pairs.csv`（避免 `data/{out_tag}_full.csv` 候选歧义）。
- **B/C 统一 `--roi-mask bbox`**：保证两臂裁剪中心一致；`masked` 的裁剪中心在代码中也是 bbox 中心（`_mask_center` 对非 centroid 一律取 `(min+max)//2`），与 `bbox` 仅差“是否把 mask 外置零”。`centroid`（质心、不屏蔽）降为历史口径对照，不参与主结论。
- **A 与 B/C 的中心未统一（本轮不改）**：ring mask 由本体 mask 膨胀而来，bbox 必然更大，其 bbox 中心与本体中心可差 1–2 体素；若强行改成同一中心需改裁剪逻辑（例如传入本体 mask 求中心）。本轮**不擅自改**，因此 **Arm A 的任何结论都必须以“中心可能偏移 1–2 体素”为前提**；统一中心登记为后续待办（§16）。
- **patient_id 一致性**：`crop_roi` 只在 mask 为空时返回 None，跳过条件（mask 缺失/空、缓存缺失）与 `roi_mask` 无关；A 与 B/C 使用同一路径的 `mr_t` mask（ring 由该 mask 派生），静态推断三臂样本集一致。**该一致性尚未实跑核对**，首次运行需比对三份 `[ROI] ... 载入 N 样本` 日志与 OOF 文件 patient_id 集合（见 §15）。
- **环宽取 5mm 而非 2mm**：96³ 覆盖 1mm bbox，单轴体素约 1–3mm，2mm 环常只有 ~1 个体素；§13.2 已在 `377`/`402` 上肉眼看到 2mm 环局部不连续。直肠系膜淋巴结短径常见 5–15mm，5mm 与目标结构尺度匹配，10mm 留作敏感性分析（本轮不跑）。

### 14.2.3 第三段：归因（4 臂，第二段结论后执行；**未执行**）

- **SDF 捷径（本轮已实现 `--sdf-only`，未执行）**：把图像通道置零、仅保留 SDF，用于排除“增益来自距离场单独携带的位置信息”。约束：隐含 `--sdf-channel`；仅 `--mask-geometry aligned`；不可与 `--roi-mask binary_only` 同用（都已属形态捷径，叠加无解释）。若 B 胜出，补跑该臂 5 折。

> 本轮仍**只改代码与文档**：无训练、无推理、无冒烟、无 GPU 调用、无影像读取、无后台任务；唯一执行是 `py_compile`。§14.2.1 标定**未启动**。

## 16.1 代码改动清单

| # | 文件 | 改动 | 说明 |
|---|---|---|---|
| 1 | `tools/aggregate_roidl_kfold.py`（新增） | 离线汇总逐折 OOF（best + `_last5`） | 只读 CSV，不加载模型/不读影像/不调 GPU；逐折 AUC/PR-AUC/F1@0.5、跨折 mean±std、Pooled OOF、跨折 LOFO 阈值与校准 F1；缺折打印 `found/missing` 后跳过；输出 `logs/aggregate_roidl_{tag}_s{seed}.json`，不覆盖 `kfold_summary_*` |
| 2 | `tools/train_roi_dl.py` | ckpt / 逐折报告 / kfold summary 补 `_s{seed}` | ckpt：`best_model[_n]_roidl_{tag}_k{fold}_s{seed}.pth`；逐折报告：`eval_report_roidl_{tag}_k{fold}_s{seed}.json`；summary：`kfold_summary_roidl_{tag}_s{seed}.json`。单 split 原本就是 `s{seed}`，命名不变 |
| 3 | `tools/train_roi_dl.py` | 成本埋点 | 每 fold 记录 `perf.epoch_sec`（逐轮）、`perf.epoch_sec_mean`、`perf.epoch_sec_total`、`perf.data_wait_ratio`、`perf.peak_gpu_mem_gb`（无 CUDA=`null`）、`perf.batch_size`、`perf.device`；写入单折报告（`result.perf`）与日志 `[ROI] kX perf: ...` |
| 4 | `tools/train_roi_dl.py` | 主表外患者显式跳过 | 打印完整 patient_id 列表，summary 增加 `n_not_in_master` 与 `not_in_master_pids`；这些样本不进入任何折，不报错、不静默纳入。口径：`hos_branch_full.csv` 相对 master 为 5 例差集；若显式 `--full-csv data/hos_pairs.csv`（356 例）则差集为 0；代码按实际差集计数打印 |
| 5 | `tools/train_roi_dl.py` | 新增 `--sdf-only` | 图像通道置零、仅保留 SDF；隐含 `--sdf-channel`；仅 `aligned`；与 `--roi-mask binary_only` 互斥（argparse 报错 + `DataROI` 兜底 ValueError） |
| 6 | `tools/train_roi_dl.py` | `_phys_filter` 补守卫 | `age∈[0,120]`、`ca199/cea ≥0`（上界 `inf`），越界转 NaN → 点亮 missing 位；避免 `log1p` 对负值产生 NaN |
| 7 | `tools/train_roi_dl.py` | `--head-dropout` 语义确认 | 默认值即 **0.5**；旧 0.3 属旧口径，随旧结果一并作废；§14 模板已显式写出 |

`py_compile` 结果：`tools/train_roi_dl.py`、`tools/aggregate_roidl_kfold.py` 均通过（Python 3.10.22，`D:\Development\miniconda\envs\Pytorch`）。
